# File Compression Agent

The File Compression Agent is a private, AWS-IAM-protected Lambda Function URL
that owns the temporary S3 staging protocol used by Nukleio and the AI agents.
It never uploads final files to Supabase and never leaves input objects in S3
after a compression attempt.

## Contract

All calls require AWS Signature Version 4, an exact caller ARN in
`NUKLEIO_COMPRESSION_CALLER_ARNS`, and these headers:

```text
x-nukleio-operation: compress_file_prepare | compress_file
x-nukleio-request-id: <UUID>
```

`POST /prepare` accepts JSON:

```json
{ "mediaKind": "portrait", "contentType": "image/jpeg" }
```

It returns an opaque `jobId` and an S3 presigned POST form. Upload the source
using that form, then call `POST /compress`:

```json
{
  "jobId": "<UUID from prepare>",
  "mediaKind": "portrait",
  "contentType": "image/jpeg"
}
```

The successful `/compress` response is binary (`image/webp` for images;
`application/pdf` for PDFs). Its output is always at most 1,048,576 bytes.
An unsuccessful compression returns a JSON `422` response with a safe reason
and detail. Inputs are deleted in a `finally` block whether compression succeeds
or fails.

Supported media kinds:

- `portrait`, `project-thumbnail`, `generated-headshot` use JPEG, PNG, or WebP input.
- `resume`, `transcript`, `generated-resume` use PDF input.

## Compression policy

Images are always emitted as WebP. The service strips metadata, normalizes to a
maximum 2,048px long edge, and finds the smallest WebP candidate satisfying a
block-SSIM score of 0.95. If that does not reach the storage cap, it falls back
through smaller dimensions down to 512px and permits SSIM down to 0.75. If the
file still cannot reach 1 MiB, it returns `422`; it never stores an unusable
output.

PDFs are first saved with safe object-stream optimization. If that remains too
large, the optional Ghostscript layer runs 144, 120, and 96 DPI lossy passes.
The 96 DPI / JPEG quality 60 pass is the final PDF floor. The service returns
`422` if it still does not fit.

## Lambda environment

Set these environment variables on each environment's Lambda:

```text
FILE_COMPRESSION_STAGING_BUCKET=nukleio-file-compression-staging-dev
NUKLEIO_COMPRESSION_CALLER_ARNS=<comma-separated exact IAM principal ARNs>
GHOSTSCRIPT_BINARY_PATH=/opt/bin/gs
```

`GHOSTSCRIPT_BINARY_PATH` is required only for lossy PDF fallback. Attach a
compatible, licensed Ghostscript Lambda layer that places `gs` at `/opt/bin/gs`.
Without it, PDFs which cannot meet the limit using safe optimization receive a
structured `422` response instead of being silently degraded.

## AWS setup

Create separate private buckets, for example:

```text
nukleio-file-compression-staging-dev
nukleio-file-compression-staging-prod
```

For each bucket:

1. Block all public access and leave ACLs disabled.
2. Enable default encryption (SSE-S3 is sufficient for this temporary data).
3. Add a lifecycle rule that expires the `incoming/` prefix after one hour.
4. Configure CORS only for the corresponding Nukleio origin and allow `POST`.
5. Do not grant public read or list permissions.

The compression Lambda execution role needs only `s3:GetObject`, `s3:HeadObject`,
and `s3:DeleteObject` on `arn:aws:s3:::<environment-bucket>/incoming/*`, plus
CloudWatch Logs writes. It does not need Supabase, database, or broad S3 access.

The identity used by each caller needs both `lambda:InvokeFunctionUrl` and
`lambda:InvokeFunction` for only the corresponding File Compression Agent. The
Function URL resource policy must allow only the same exact principals, with
`AWS_IAM` authentication. The app's IAM principal and the Resume/Headshot agent
execution roles belong in `NUKLEIO_COMPRESSION_CALLER_ARNS`.

The caller that uploads to S3 must receive only the presigned POST generated by
`/prepare`; it needs no S3 IAM credentials. The upload URL expires after five
minutes and can write exactly one randomized `incoming/<jobId>` key.
